# Задание R1.2:Mod2 — Модель метода

Статус: закрыто с двумя примерами вместо трёх (сессия закрыта по решению Марии — контекст разросся). Характеристика объекта в примере 2 найдена 28.09.2026 (сессия 11). Характеристика в примере 1 помечена открытой 28.09.2026 — см. примечание под таблицей примера 1.

## Пример 1 — Паспорт проекта по 6 осям

| Поле | Значение |
|---|---|
| Задача | Подготовить паспорт проекта по 6 осям к рассмотрению на СД |
| Цель | Предоставить данные совету для принятия инвестиционного решения |
| Польза | Предотвращение траты времени и денег на неподходящий проект |
| Результат | Заполненный паспорт |
| Метод | Заполнить паспорт |
| Объект | Документ (паспорт проекта) |
| Характеристика | Структура/шаблон (состав и число разделов, неизменны при любом % заполнения) — **открыто, см. примечание** |
| Состояние | % заполнения (раздел не считается заполненным без подтверждённого качества — качество не отдельное состояние, а критерий внутри самого % заполнения) |
| Действие | Сбор и обработка информации по разделу |

**Примечание (28.09.2026):** характеристика «шаблон» подобрана по критерию «характеристика не меняется между состояниями объекта». Этот критерий ввёл агент в сессии 9, в учебнике (пройденные разделы R1.1–R1.2) его нет. По R1.1:6 характеристика — свойство вещи (часто слово на -ость), важное для метода. Характеристику паспорта не переделывали — оставлена открытой.

## Пример 2 — Обучение инструменту (акселератор «Каталист»)

| Поле | Значение |
|---|---|
| Задача | Провести обучающее мероприятие по конкретному инструменту в рамках акселератора «Каталист» |
| Цель | Обучить студентов инструменту для применения в их проектах |
| Польза | Меньше ошибок в работе над проектом, выше шанс успешной реализации, экономия времени на самостоятельном сборе граблей |
| Результат | Проверенное умение студента применять инструмент (подтверждено принятой домашкой/артефактом) |
| Метод | Обучить инструменту |
| Объект | Студент Каталиста |
| Характеристика | Владение инструментом |
| Состояние | Не владеет → владеет (применяет инструмент в своём проекте) |
| Действие | Рассказать/показать → ответить на вопросы → домашка с применением к проекту → проверка сданного артефакта |

## Было / стало

**Пример 1:** результат утыкался в решение СД (деньги вложены/отказано) вместо самого паспорта; метод назывался как документ, а не как действие; польза не заполнена; характеристика была слита с действием («задав вопросы, собрав информацию»). После разбора — все девять полей про один и тот же объект и его жизненный цикл: документ от 0% до 100% заполнения, метод — глагол над ним, польза отдельно от цели, характеристика (шаблон) отдельно от состояния (%).

**Пример 2:** метод был названием типа мероприятия («мероприятие акселератора»), не действием; объект — «наверное студенты», без уверенности; польза улетала на выход всего акселератора («получаются стартапы»). После разбора 27.09 — метод «обучить инструменту» (конкретная последовательность, которую можно поручить методисту), польза — про эффект прямо сейчас (меньше ошибок, экономия времени), а не про отдалённый и не полностью зависящий от этого мероприятия результат.

**Пример 2, правка 28.09.2026:**

| Поле | Было (27.09) | Стало (28.09) |
|---|---|---|
| Объект | Навык владения инструментом (у студента) | Студент Каталиста |
| Характеристика | Не найдена — открытый вопрос | Владение инструментом |
| Состояние | Не умеет → умеет | Не владеет → владеет (применяет инструмент в своём проекте) |

Вывод: объектом метода была поставлена характеристика — поэтому характеристика и не находилась. По R1.1:6 свойство без вещи смысла не имеет; вещь — студент, свойство — владение инструментом. Первоначальный вариант Марии («наверное студенты») был верным; на «навык» разбор увёл агент.
