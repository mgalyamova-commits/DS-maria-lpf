# Задание R1.2:Mod4 — Описываем работы по методу

**Дата:** 28.09.2026 · **Сессия трека:** 11 · **Опора:** методы из R1.2:Mod2 (см. `r1-2-mod2-model-metoda.md`): пример 1 — «Заполнить паспорт», пример 2 — «Обучить инструменту»

Формулировка задания: вернуться к одному из методов из R1.2:Mod2 и расписать, какие работы надо выполнить, чтобы исходная задача была решена этим методом. Работ может быть несколько; рабочий продукт и агент могут меняться от работы к работе, а если остаются прежними, продукт меняет состояние.

Сделано два примера: 1 — описание **фактической** работы (Химозин, уже выполнено); 2 — описание **планируемой** работы (практикум CusDev в Каталисте, 02.10.2026).

---

## Пример 1 — Паспорт проекта Химозин (фактическая работа)

### Работы

| # | Работа | Результат (рабочий продукт + состояние) | Агент-исполнитель | Скорость |
|---|---|---|---|---|
| 1 | Прогнать скрипт IWE по исходникам и черновику паспорта от заявителя | Паспорт v1, автозаполненный | инвест-аналитик (Мария) | 0,5 ч |
| 2 | Вычитать, проверить корректность, отметить пробелы и что требует проверки | Паспорт + список пробелов | инвест-аналитик (Мария) | 1 ч |
| 3 | Дособрать информацию: открытые источники + вопросы заявителю | Доп. исходники | инвест-аналитик (Мария) + заявитель Химозина | 1 день |
| 4 | Повторный прогон скрипта (скрипт собирает все исходники в паспорт) | Паспорт vN | инвест-аналитик (Мария) | 0,5 ч |
| | *2–4 повторяются циклом, пока пробелы не закрыты* | | | |
| 5 | Собрать папку со всем, на что ссылается паспорт | Папка исходников | инвест-аналитик (Мария) | 0,5 ч |
| 6 | Финальная проверка: непротиворечивость и выводы; отправка заявителю | Паспорт на проверке у заявителя | инвест-аналитик (Мария) | 0,5 ч |
| 7 | Подтвердить информацию о своём проекте | Паспорт подтверждён заявителем | заявитель Химозина | по ответу заявителя |
| 8 | Разослать на СД (строго после строки 7) | Паспорт в рассылке СД | инвест-аналитик (Мария) | минуты |

**Общее на все работы:**
- Задача — подготовить паспорт проекта Химозин по 6 осям к рассмотрению на СД
- Инструмент физический — компьютер с интернетом и подключённым IWE
- Ресурсы — время, токены Claude, электричество, место в облачном хранилище
- Срок — к дате СД

### Было / стало

| Поле | Было (черновик) | Стало |
|---|---|---|
| Задача | Подготовить паспорт по 6 осям к СД | Подготовить паспорт **Химозина** к СД |
| Результат | Заполненный паспорт, отправляется по почте | Свой у каждой работы: паспорт v1 → паспорт + список пробелов → доп. исходники → паспорт vN → папка исходников → паспорт на проверке у заявителя → паспорт подтверждён → паспорт в рассылке СД |
| Агент | Инвест-аналитик | Инвест-аналитик (Мария) + заявитель Химозина (строки 3 и 7) |
| Работа | Шесть шагов одной строкой | 8 работ по строкам, цикл 2–4 до закрытия пробелов, рассылка на СД строго после подтверждения заявителя |
| Инструмент | Компьютер с интернетом и IWE | без изменений, общий на все работы |
| Ресурсы | Время, токены, электричество, облако | без изменений, общие |
| Срок | — | к дате СД |
| Скорость | От 1 дня до 1 месяца | По строкам (см. таблицу). Работа Марии — около 3 ч + день на дособор; разница до месяца — ожидание ответов заявителя, это не работа |

### Вывод

Работа Марии по паспорту занимает часы; календарь съедает ожидание заявителя. Порядок «подтверждение заявителем → рассылка на СД» исправлен по ходу разбора (в практике рассылка шла параллельно с проверкой заявителем).

## Пример 2 — Практикум по CusDev в Каталисте (планируемая работа)

Метод из Mod2: «Обучить инструменту». Объект — студент Каталиста; характеристика — владение инструментом; состояния — не владеет → владеет.

Экземпляр: практикум по CusDev, **02.10.2026 (пятница)**, спикер — **Никита Николаенко**, ожидается 50–70 студентов.

### Работы

| # | Работа | Результат (рабочий продукт + состояние) | Срок |
|---|---|---|---|
| 1 | Согласовать сценарий со спикером: длительность лекции, активность и что для неё нужно, баллы за активность, проверка артефактов, домашка | Параметры практикума согласованы | вт 29.09, планёрка Каталиста |
| 2 | Записать в сценарий (паспорт сценария ещё не доработан) | Сценарий практикума | вт 29.09, планёрка |
| 3 | Анонсировать по доступным каналам (с плюшками и бонусами); подготовка анонса — на планёрке | Анонс опубликован | 29–30.09 |
| 4 | Подготовить реквизит, интерактив, инфраструктуру площадки | Всё нужное для активности есть | 30.09–01.10 |
| 5 | Подготовить площадку: презентация, микрофоны, рассадка, реквизит, подключения | Площадка готова | пт 02.10, до начала |
| 6 | Провести по сценарию вместе со спикером: лекция → практическое задание → обратная связь по нему | **Студент: не владеет → владеет CusDev** | пт 02.10 |
| 7 | Начислить баллы и бонусы за активность, сообщить студентам | Баллы начислены, студенты знают | сб 03.10 |
| 8 | Объявить домашку | Домашка выдана | пт 02.10 |
| 9 | Собрать домашку | Домашки сданы | до пт 09.10 |
| 10 | Проверить домашку | Владение подтверждено (или нет) | до пт 09.10 |
| 11 | Начислить бонусы за домашку | Бонусы начислены | до пт 09.10 |
| 12 | Внутренний постмортем: что так, что не так | Разбор зафиксирован | вт 06.10, планёрка (см. «Открыто») |
| 13 | Обновить документацию мероприятия (сценарий, домашки) | Документация обновлена | после постмортема |

**Общее:** исполнители — по ролям команды Каталиста (распределение ролей у команды есть, сюда не дублируется); спикер — строка 6. Инструмент, ресурсы и скорость в этом примере не разбирались (план, а не замер).

| Результат | — | Свой у каждой работы: параметры согласованы → сценарий → анонс опубликован → реквизит и инфраструктура готовы → площадка готова → студент: не владеет → владеет CusDev → баллы начислены → домашка выдана → сдана → владение подтверждено → бонусы начислены → разбор зафиксирован → документация обновлена |

### Открыто

- **Постмортем** стоит 06.10, раньше дедлайна домашек 09.10 — на нём не будет видно, сработал ли практикум. Два постмортема для команды тяжело. Варианты: (а) один постмортем 13.10, после проверки домашек; (б) постмортем 06.10 + на планёрку 13.10 одна цифра — сколько сдали домашку и прошли проверку. Не решено.
- **Паспорт сценария не доработан** — строка 2 опирается на недоделанный шаблон; доработка до строки 2 или по ходу — не решено.

### Вывод

Из 13 работ только строка 6 меняет состояние объекта метода «обучить инструменту»; остальные — работы по другим методам (организация, анонс, начисление бонусов, разбор), которые обслуживают это изменение. Этот пример — вход для будущего инструмента в Claude, который собирает такие планы и сверяет план с фактом (задача не трека обучения — ветка Каталиста / IWE_Церен).
