# Агент разбора биологических вакансий (hh.ru) — спецификация v2

> **Статус:** версия 2, 20.10.2026, слоты `пиш-1020-ч2/1` и `пиш-1020-ч2/2`. Заменяет `2026-10-20-agent-razbora-vakansij-bio-spec-v1.md` (v1 оставлена как есть, для истории). Правки внесены после первой проверки на 8 вакансиях (раздел 7). Правки приняты Марией («гейт да»). Адресат — Слава (Лебеденко): сборка и первый настоящий прогон на 30–50 вакансиях. Цель — типичные рабочие задачи рынка как вход для гипотез курсов ДПО БИО (дальше — метод `2026-10-19-metod-proverki-gipotezy-kursa-bio.md`).
>
> **Что не проверено:** условия доступа к API hh.ru на сегодня (по найденным источникам нужен токен приложения и заголовок `HH-User-Agent`); предельная глубина выдачи; наличие и качество полей `description`, `key_skills`, `experience`, `published_at`, `archived` в карточке вакансии. Схема на полных текстах вакансий ещё ни разу не гонялась.

## 1. Как устроено (способ 2: скрипт + модель)

1. **Сбор.** Скрипт ходит в API hh.ru: поиск по набору запросов → список id → полная карточка каждой вакансии.
2. **Фильтр до модели (скрипт, без модели):** отбросить дубли по правилу раздела 2, вакансии вне выбранной страны и периода, вакансии с неполным описанием (раздел 3, шаг 0).
3. **Разбор.** Каждая карточка отдельно уходит в Claude с инструкцией раздела 4; ответ — JSON по схеме.
4. **Проверка цитат.** Скрипт сам ищет каждую цитату в тексте вакансии. Не нашлась → задача помечается «без цитаты» и в подсчёт не идёт.
5. **Кластеры и частотность.** Нормализация задач в кластеры (вторым проходом модели по списку формулировок), подсчёт по числу разных вакансий.
6. **Выход.** Таблица для Марии (раздел 5).

## 2. Сбор с hh.ru (для Славы)

- Регистрация приложения и токен — dev.hh.ru → «Мои приложения». В каждом запросе заголовок `HH-User-Agent` (название приложения и контактный email); без него hh отклоняет запросы.
- Поиск: `GET https://api.hh.ru/vacancies`, параметры `text`, `area`, `search_field`, `per_page`, `page`. Полная карточка: `GET /vacancies/{id}`; описание приходит HTML — перед разбором очистить в текст. Названия параметров и поля ответа сверить с документацией и живым ответом.
- **Описание брать только из API.** Страница вакансии на hh.ru без скрипта описание не отдаёт, а выдержки из поисковиков режут списки обязанностей. Разметка по таким огрызкам бессмысленна.
- Регион: для первой проверки — вся Россия (`area=113`), потом отдельный срез по Новосибирску для сравнения.
- Период: фиксировать при запуске (например, публикации за последние 6 месяцев) и писать в шапку результата. Архивные вакансии брать, если дата публикации в периоде; помечать `archived`.
- Первый набор запросов по сегментам (подбирает Слава, это старт):
  - A исследовательский: «молекулярный биолог», «научный сотрудник биолог», «лаборант-исследователь».
  - B биотех, фарма, агро: «биотехнолог», «микробиолог», «селекционер», «технолог биотехнологического производства».
  - C данные: «биоинформатик», «bioinformatics», «аналитик данных геномика».
  - D диагностика: «специалист ПЦР-лаборатории», «биолог клинической лаборатории».
- Выборка первой проверки: по 8–12 вакансий на запрос, всего 30–50.
- **Правило дублей:** вакансия — дубль, если совпадает (почти) весь текст обязанностей, независимо от города и названия. Один работодатель с разными задачами в разных городах — не дубль. Скрипт сравнивает тексты, модель этого не делает.
- Сохранять сырой JSON каждой карточки в папку прогона (id, дата выгрузки, текст). Без сырья нечем проверять цитаты и нечего перезапускать.

## 3. Шаг 0 — фильтр полноты (скрипт, до модели)

- Вакансия **неполная**, если в тексте меньше трёх пунктов обязанностей или нет блока задач вообще. Неполные идут в отдельный список «не разметили», в частотность не входят.
- Страна не из заданного списка (для старта: Россия) → в отдельный список, в подсчёт не идёт. Источник страны — поле региона вакансии, не догадка модели.
- Опыт (`experience`) берётся из поля hh и копируется в результат как есть (нет опыта / 1–3 / 3–6 / более 6), модель его не оценивает.

## 4. Инструкция для модели (на каждую вакансию)

```
Ты размечаешь одну вакансию в области биологии для ДПО ПИШ НГУ. Верни только JSON.

Поля: vacancy_id, employer, title, segment, level_from_text, tasks, tools,
learnable_requirements, experience_requirements.

segment определяй по РАБОЧИМ ЗАДАЧАМ, а не по профилю работодателя или названию:
A исследовательский (лаборатория, НИИ, вуз); B биотех/фарма/пищепром/агро;
C биоинформатика/анализ данных; D медицинский/диагностический;
E не биология (например, поддержка АСУТП или разработка ПО в биотех-компании).

level_from_text: junior / middle / senior / руководитель — по тому, ЧТО человек
делает по тексту (руководит группой, ведёт проект, выполняет по инструкции).
Название должности может не совпадать с содержанием: опирайся на текст. Если
текст и название расходятся, добавь поле "расхождение": "<коротко>".

tasks: от 3 до 10 пунктов. Каждый — {text, quote}:
- text — что человек делает, глаголом («проводит ПЦР-диагностику»,
  «обрабатывает данные NGS»); не «ответственный за», не «обязанности включают»;
- quote — фрагмент текста вакансии ДОСЛОВНО, не длиннее 15 слов.
Задачу, которой нет в тексте, не добавляй. Дословной цитаты нет — quote
пустая строка, задача получает пометку "без цитаты". Вывод, который ты
делаешь сама, помечай "предположение": true.

tools — названия методов, стандартов и программ из текста (R, Python, qPCR,
LC-MS/MS, GMP, GLP, Galaxy…).
learnable_requirements — требования, которые реально получить обучением
(методы, стандарты, программы, знания). experience_requirements — требования вида
«опыт N лет», «публикации», «допуск».

Не по теме — segment E, tasks пусто. Данных мало — не домысливай, верни то,
что есть, и "мало_текста": true.
```

Второй проход (нормализация), на список всех пунктов `tasks.text` из выборки:

```
Объедини задачи одинакового смысла в кластеры. Для каждого кластера: название
глаголом, список вариантов формулировок, id вакансий. Задачи, которые не
складываются ни с чем, оставь отдельными. Ничего не придумывай: кластер состоит
только из пришедших формулировок.
```

## 5. Формат результата

1. **Шапка:** период, страна, запросы, дата выгрузки, сколько вакансий выгружено / отброшено как дубли / отброшено как неполные / вне страны / сегмент E / вошло в разбор, разбивка по сегментам.
2. **Таблица кластеров:** кластер | вакансий (N и % от вошедших в разбор) | сегменты | типичные инструменты | опыт по полю hh | две цитаты с id вакансии.
3. **Длинный хвост:** кластеры реже 5%.
4. **Не удалось разметить:** списки id по причинам (неполный текст, вне страны, не по теме, нет цитаты).
5. **Для топ-10 кластеров** пометка модели: «осваивается обучением за недели» / «требует практики на реальных образцах или данных» / «не определено» — это предположение, помечено как предположение.

Частота = число РАЗНЫХ вакансий с кластером ÷ число вакансий, вошедших в разбор (не число упоминаний и не число выгруженных). Выводов про цены, спрос на курсы и «что запускать» агент не делает: гипотезы курсов строятся отдельным шагом.

## 6. Как понять, что схема годится (предложение, Слава вправе поправить)

- Цитаты: доля задач с найденной в тексте цитатой — не ниже 90%, считается только по полным текстам; ниже — править инструкцию, а не принимать.
- Повторяемость: два прогона одних и тех же 40 вакансий дают в топ-10 кластеров не меньше семи общих.
- Ручная сверка: Слава берёт 5 вакансий, читает глазами и сравнивает с разметкой; расхождения приносит списком.
- Доля отброшенных как неполные: если больше 20% выгрузки, проблема в сборе (описание не пришло), а не в схеме.

## 7. Что показала первая проверка (20.10.2026, слот `пиш-1020-ч2/2`)

Проверка шла без API: из среды Claude `api.hh.ru` недоступен (защита от ботов), страницы вакансий отдают шапку без описания, открытые данные «Работы в России» запрещают автоматический доступ. Разметка делалась по 8 выдержкам из поисковой выдачи (6 с hh.ru, 1 Quantori Астана, 1 стажёр BIOCAD), поэтому это проверка схемы, а не рынка.

- У 3 из 6 hh-вакансий блок задач пришёл пустым или с одним пунктом → шаг 0 и правило «описание только из API».
- Вакансия с названием «научный сотрудник» по тексту ищет руководителя группы → `level_from_text` и поле `расхождение`.
- Стажёр АСУТП в биотех-компании не про биологию → сегмент по задачам.
- Вакансия из Астаны и документ 2021 года в одной выборке → фильтры по стране и дате.
- Две вакансии оказались в архиве → поле `archived`, правило периода.
- Одно название в разных городах → правило дублей по тексту.
- Предварительные кластеры на 5 вакансиях с текстом (n слишком мало для статистики): лабораторная и технологическая документация; контроль соответствия GMP/GLP/ОТ; проведение испытаний и исследований; разбор отклонений и оптимизация процесса; приготовление смесей и растворов по рецептуре.
