## 1. Общие сведения

### 1.1. Исходное состояние разработки

На данный момент выполнено: изготовлены два функционирующих прототипа модулей в уменьшенном масштабе (габариты 900×180×95 мм, корпус — фанера, подъёмная платформа — сталь); подтверждена работоспособность кинематической схемы и механизма подъёма паллеты в режиме ручного управления с пульта; реализована базовая SLAM-навигация одного модуля на основе готового ROS-пакета с одним лазерным лидаром; автономное движение, синхронизация модулей, автоматический заезд под паллету и работа с номинальной нагрузкой не реализованы.

### 1.2. Цель работы и результат этапа

Цель — создать и испытать полноразмерный опытный образец системы, выполняющий полный транспортный цикл в автоматическом режиме без участия оператора: приём задания из веб-интерфейса, автономный проезд к паллете, выравнивание и заезд под неё, синхронный подъём, транспортировка и опускание в заданной точке.

Результат этапа: два полноразмерных роботизированных модуля в металлическом исполнении с номинальной суммарной грузоподъёмностью 800 кг; комплект ПО (бортовое на базе ROS 2, ПО синхронизации, веб-интерфейс оператора); симуляционная модель системы и виртуального склада; комплект КД, программной и эксплуатационной документации.

Целевой уровень готовности технологии по завершении работ — **TRL-6**.

### 1.3. Сроки

Общий срок выполнения работ — **6 календарных месяцев** с даты начала работ.

### 1.4. Термины и сокращения

AMR — Autonomous Mobile Robot. APR — Autonomous Pallet Robot. DDS — Data Distribution Service. E-Stop — аварийная остановка. FSM — конечный автомат. IMU — инерциальный измерительный модуль. Nav2 — Navigation2 (штатный навигационный стек ROS 2). ROS 2 — дистрибутив Jazzy Jalisco. SLAM — одновременная локализация и построение карты. TF/TF2 — дерево координатных преобразований. URDF — формат описания кинематики и геометрии робота. VDA 5050 — отраслевой стандарт обмена сообщениями РМС↔робот. WMS/ERP — система управления складом / планирования ресурсов. EUR-паллета — 1200×800×144 мм по EN 13698-1/ГОСТ 9078-84. Master/Slave — ведущий/ведомый модуль пары. КД/ПМИ — конструкторская документация / программа и методика испытаний. TRL — уровень готовности технологии.

## 2. Назначение, состав и границы работ

### 2.1. Назначение изделия

Автономное горизонтальное перемещение стандартных EUR-паллет с грузом внутри отапливаемых складских/производственных помещений без участия оператора. Принципиальное отличие от решений класса APR: два независимых модуля заезжают в продольные проёмы паллеты с одной стороны, приподнимают её на минимальную высоту и перемещают горизонтально — компактный размер и практически нулевая добавочная высота груза.

### 2.2. Состав опытного образца

1. Модуль роботизированный, 2 шт. — корпус, ходовая часть, подъёмный механизм, сенсорная подсистема, вычислитель, контроллер приводов, АКБ, средства сигнализации и аварийной остановки.
2. Бортовое ПО модуля — пакеты ROS 2: драйверы, одометрия, SLAM, Nav2, синхронизация, выравнивание и заезд, диагностика, аварийные режимы.
3. Серверное ПО и веб-интерфейс — веб-приложение оператора, шлюз rosbridge, менеджер миссий, хранилище карт и журналов событий, внешний API.
4. Симуляционная модель — URDF/xacro-модели модуля и пары, модель EUR-паллеты, SDF-модель виртуального склада, launch-файлы, тестовые сценарии.
5. Комплект документации — конструкторская, программная, эксплуатационная.

### 2.3. Условия эксплуатации опытного образца

Внутри отапливаемых помещений, +5…+40 °C, влажность ≤80% без конденсации, твёрдое ровное напольное покрытие, уклон пола ≤2°, перепад (стык/порог/трещина) ≤5 мм по высоте / ≤15 мм по ширине, освещённость не нормируется для лидарной навигации (для QR — не менее 50 лк), ширина рабочего прохода ≥1200 мм, ширина поперечного проезда для разворота ≥2000 мм, режим — огороженная/выделенная зона под наблюдением оператора.

### 2.4. Демонстрационный сценарий (главный критерий готовности этапа)

1. Картографирование — оператор проводит модуль вручную, система строит карту SLAM.
2. Разметка зон — оператор задаёт зону A (забор), зону Б (выгрузка), зоны запрета.
3. Постановка задачи — «забрать в A, доставить в Б».
4. Проезд к паллете — автономно, объезд препятствий.
5. Выравнивание — по лидару (геометрия) и QR-коду (идентификатор).
6. Заезд — синхронно, на пониженной скорости, контроль бокового отклонения.
7. Подъём — синхронный, режим связки.
8. Транспортировка — пара перевозит паллету, удерживая рассогласование в допуске.
9. Выгрузка — синхронное опускание, выезд, возврат в зону ожидания.
10. Отчёт — статус «выполнено», журнал событий, телеметрия.

### 2.5. Границы работ (сознательно НЕ входит в этап, срок 6 мес.)

- Интеграция с WMS/ERP и полная реализация VDA 5050 (только совместимый по структуре внешний API) — этап пилотного внедрения.
- Автозарядная станция/автодокинг (только заряд по кабелю, место под контактную группу) — следующий этап.
- Система управления парком (RMS), работа >1 пары, разрешение конфликтов трафика.
- Работа со стеллажами выше первого яруса, штабелирование.
- Сертификация (ТР ТС 010/2011, ГОСТ Р 60.6.2.1/ISO 3691-4), сертифицированные лидары безопасности PL d — опытный образец не является продукцией, выпускаемой в обращение.
- Паллеты нестандартных типоразмеров/повреждённые (испытания на EUR 1200×800, FIN 1200×1000 — опционально).
- Эксплуатация вне помещений, при отрицательных температурах, во влажных/взрывоопасных средах.
- Технологическая подготовка серийного производства, оснастка, себестоимость серийного изделия.
- Ресурс/наработка на отказ на уровне серийного изделия.

## 3. Основные технические характеристики (целевые, подтверждаются испытаниями по разделу 7)

### 3.1. Массогабаритные и грузовые

Габариты модуля ≤1400×200×95 мм. Масса модуля без груза ≤90 кг. Грузоподъёмность пары ≥800 кг, одного модуля ≥400 кг. Коэффициент запаса прочности несущих элементов ≥1,5. Остаточная деформация после снятия номинальной нагрузки — отсутствует. Ход подъёмного механизма 30–50 мм. Просвет между настилом паллеты и полом после подъёма ≥20 мм. Добавочная высота груза ≤50 мм. Рассинхронизация высоты подъёма между модулями ≤5 мм.

### 3.2. Ходовые характеристики

Макс. скорость с грузом в открытой зоне ≥1,0 м/с. Скорость в узком проходе 0,3–0,5 м/с (параметрируется). Скорость въезда в проём паллеты 0,05–0,10 м/с. Макс. ускорение/замедление ≤0,5 м/с². Тормозной путь при аварийной остановке со скорости 1,0 м/с с грузом ≤0,5 м. Время полной остановки при E-Stop ≤1,0 с. Преодолеваемый уклон с грузом ≥2°. Преодолеваемый порог ≥5 мм.

### 3.3. Геометрия рабочей зоны

Мин. ширина прохода для прямолинейного движения пары с паллетой ≤1200 мм; для одиночного модуля без груза ≤900 мм. Мин. ширина поперечного проезда для разворота на 90° ≤2000 мм. Свободная зона перед паллетой для выравнивания и заезда — не менее 2000 мм по оси прохода. Компенсируемое начальное угловое отклонение паллеты ≥±10°. Компенсируемое начальное боковое смещение модуля ≥±150 мм.

### 3.4. Точность и синхронизация

Точность позиционирования модуля в конечной точке — линейная не хуже ±50 мм, угловая не хуже ±2°. Боковое отклонение при выравнивании (ось Y) ≤±5 мм, угловое рассогласование ≤±1°. Взаимное продольное рассогласование модулей при совместном движении ≤±20 мм, угловое ≤±1,5°. Накопленная ошибка локализации на маршруте 100 м с возвратом ≤100 мм.

### 3.5. Энергетика и производительность

Время непрерывной автономной работы в типовом цикле ≥4 ч (типовой цикл: 50% движение с грузом, 30% без груза, 20% ожидание). Потребляемая мощность модуля в движении с грузом ≤1000 Вт. Время заряда АКБ 20→90% ≤2 ч. Производительность на плече 100 м ≥8 циклов/час. Доля успешных автоматических циклов в серии из 50 ≥90%.

## 4. Требования к аппаратной части

### 4.1. Конструкция модуля

Плоская вытянутая платформа прямоугольного сечения, сталь и/или алюминиевые сплавы, ЧПУ-обработка (фрезерная, токарная, лазерная резка, гибка). Плоская компоновка, высота профиля ≤95 мм. Жёсткость корпуса — удержание 400 кг на модуль без остаточной деформации, расчётный прогиб несущей балки ≤3 мм. Скошенный/скруглённый передний торец под наезд на порог до 5 мм. Притупленные внешние кромки, отсутствие выступающего крепежа над верхней плоскостью. Модули идентичны и взаимозаменяемы (роль master/slave задаётся ПО, не аппаратно). Степень защиты не ниже IP20.

### 4.2. Ходовая часть и привод

Велосипедная схема: одно заднее ведущее колесо, одно переднее поворотное (управляемое). Материал колёс — полиуретан/капролон. Допустимая статическая нагрузка на колесо ≥250 кг, запас ≥1,5. Привод ведущего колеса — мотор-редуктор DC/BLDC, крутящий момент обеспечивает трогание на уклоне 2° и разгон до 1,0 м/с. Диапазон поворота рулевого колеса ≥±45° (целевое ±60°). Инкрементальные энкодеры на обоих моторах, на рулевом — дополнительно абсолютный датчик угла/концевик. Разрешение одометрии не хуже 1 мм / 0,1°.

### 4.3. Подъёмный механизм

Электрический линейный актуатор + рычажная система. Номинальная нагрузка 400 кг/модуль, запас ≥1,5, подтверждение статикой на 600 кг/модуль. Ход подъёма 30–50 мм. Самоторможение (винтовая передача/механический фиксатор) — самопроизвольное опускание не допускается. Время полного подъёма/опускания ≤10 с. Датчики крайних положений + контроль тока актуатора (контакт с паллетой, перегрузка, заклинивание).

### 4.4. Система электропитания

АКБ LiFePO4, напряжение шины 24–48 В, ёмкость из расчёта ≥4 ч работы, но не менее 1,0 кВт·ч/модуль. BMS обязательна (перезаряд/переразряд/перегрузка/КЗ/перегрев, балансировка). Телеметрия батареи в ROS 2 и веб-интерфейсе. Пороги: SoC≤20% — предупреждение и запрет новых задач; ≤10% — завершение задачи, режим ожидания заряда; ≤5% — блокировка движения. Зарядка — ручное подключение кабеля (место под контактную группу для будущего автодокинга предусмотрено конструктивно). Раздельные силовые/вычислительные цепи. Главный выключатель, предохранители, защита от переполюсовки.

### 4.5. Сенсорная подсистема

2D-лидары ×2 на модуль (передний/задний), обзор ≥180°, дальность ≥10 м, частота ≥10 Гц, погрешность ±30 мм, разрешение ≤1°, плоскость сканирования 40–70 мм от пола. IMU ×1 (≥6 осей, ≥100 Гц). Энкодеры приводов ×2. Камера ×1 обязательно (передняя, QR-код, ≥1280×720, ≥90° по горизонтали, ≥15 к/с), ×1 опционально (задняя). Датчики подъёмного механизма (концевики, наличие паллеты, ток актуатора). Контроль тока/температуры каждого мотора.

### 4.6. Вычислительная платформа и контроллер приводов

Одноплатный компьютер ≥4 ядра ≥1,5 ГГц, ОЗУ ≥8 ГБ, накопитель ≥128 ГБ (базовая платформа — Raspberry Pi 5 8 ГБ или аналог). ОС Ubuntu 24.04 LTS, ROS 2 Jazzy Jalisco. Контроллер приводов — микроконтроллер по UART, замкнутые контуры регулирования, сторожевой таймер (остановка при отсутствии команд >300 мс). Загрузка до готовности ≤90 с. Сервисный SSH-доступ.

### 4.7. Каналы связи

Wi-Fi 5 ГГц, ROS 2 DDS. Частота обмена master↔slave ≥20 Гц, задержка ≤50 мс на 95-м процентиле, потеря heartbeat >500 мс = отказ связи. Исследовательская проработка резервного радиоканала (868/915 МГц или 2,4 ГГц FHSS) — факультативно. Аварийная остановка при отказе связи выполняется каждым модулем локально, без зависимости от Wi-Fi.

### 4.8. Требования безопасности

Опытный образец НЕ является сертифицированным промышленным оборудованием; все испытания — в выделенной/огороженной зоне под наблюдением оператора. Средства: аппаратная кнопка E-Stop (грибовидная, аппаратное размыкание силовой цепи, ручной сброс), программный E-Stop в веб-интерфейсе, двухзонная схема безопасности по лидару (зона предупреждения / зона остановки, параметры зависят от скорости — при 1,0 м/с зона остановки ≥800 мм, при 0,3 м/с ≥300 мм), блокировка подъёма (только при нулевой скорости и подтверждённом положении обоих модулей в проёмах), ручной режим (только при остановленной системе, автономные функции блокируются).

### 4.9. Требования к надёжности и ремонтопригодности

Наработка в ходе испытаний ≥50 циклов и ≥20 ч без критических отказов. Замена колеса/АКБ/лидара — один человек, ≤1 час, штатным инструментом. Разъёмные электрические соединения, защита кабельных трасс. Компоненты — с учётом доступности на рынке РФ и наличия альтернативного поставщика для критичных позиций.

## 5. Требования к программному обеспечению

### 5.1. Архитектура и стек

ОС Ubuntu 24.04 LTS, ROS 2 Jazzy Jalisco, C++/Python 3. Навигация — Nav2. SLAM — slam_toolbox (базово), cartographer как альтернатива. Симуляция — Gazebo Harmonic/Fortress + ros_gz_bridge. Веб-интерфейс — React + rosbridge_suite (WebSocket). Конфигурация — YAML без пересборки. Хранение — карты .pgm+.yaml на master, журналы — SQLite/файловый с ротацией.

Схема «ведущий-ведомый»: master — SLAM, глобальное/локальное планирование системы, менеджер миссий, обмен с сервером; slave — исполнение команд скорости, собственная одометрия, локальная безопасность, подтверждение переходов состояний. Роль — параметр запуска, пакеты идентичны у обоих. Пространства имён разделены по модулям (/module_1, /module_2), общесистемные топики — в глобальном пространстве.

### 5.2. Драйверы и базовые узлы

Драйвер приводов: приём Twist-команд, прямая/обратная велосипедная кинематика, публикация /joint_states и /odom с ковариацией, контроль связи с контроллером (>300 мс — ошибка+остановка). Драйвер лидаров: объединение в /scan_merged (расхождение временных меток ≤20 мс), фильтрация самозатенения. Драйвер IMU: публикация /imu/data с фильтрацией шума, robot_state_publisher по URDF/xacro, фреймы map/odom/base_link/front_lidar/rear_lidar/front_camera/rear_camera/imu/lift_link/steer_link/drive_wheel, слияние одометрии+IMU+скан-матчинга (robot_localization).

### 5.3. SLAM и управление картами

Построение карты лазерным SLAM (online mapping), параметризация (разрешение карты 0,05 м базово, порог качества замыкания цикла, частота обновления). Локализация на сохранённой карте с обоими лидарами+энкодерами+IMU. При недостаточной точности узких проходов — приоритет мер: слияние с одометрией/IMU → визуальная одометрия → искусственные ориентиры (крайняя мера). Управление картами через веб-интерфейс. Хранение семантической разметки (зоны A/Б/ожидания/заряда, запрета, ограничения скорости). При потере локализации — остановка, до 3 попыток релокализации, затем аварийное состояние.

### 5.4. Автономная навигация

Полный стек Nav2 (глобальный планировщик, локальный контроллер, карты стоимости, поведения восстановления, bt_navigator). Глобальный — Smac Planner (неголономный, реверс), допускается NavFn для отладки. Локальный — с учётом велосипедной кинематики. Раздельные футпринты для одиночного модуля и связки (габарит связки ≥1400×1200 мм), переключение автоматически. Обработка динамических препятствий — снижение скорости/объезд/остановка. Поведения восстановления: ожидание, отъезд назад, повторное планирование (разворот на месте не применяется). Keepout-зоны и зоны ограничения скорости через фильтры карт стоимости. Приём задач — ROS 2 Action Server, совместимый с navigate_to_pose.

### 5.5. Синхронизация пары модулей

Протокол master↔slave: master → slave — целевая скорость, команда подъёма, режим, метка времени, счётчик пакетов; slave → master — одометрия, статус приводов, состояние подъёма, код ошибки, подтверждение, состояние зон безопасности. Частота ≥20 Гц, heartbeat ≥10 Гц в обе стороны, потеря >500 мс — аварийная остановка обоих. Синхронизация движения в связке: master рассчитывает траекторию системы как единого целого с учётом геометрического смещения; коррекция скорости отстающего/опережающего модуля; превышение допустимого рассогласования — контролируемая остановка, попытка выравнивания, при неуспехе — авария с удержанием груза. В режиме связки SLAM — только на master; slave вычисляется относительно него.

### 5.6. Выравнивание и заезд под паллету (конечный автомат)

APPROACH (подход ~1,0–1,5 м, грубая ориентация по QR+геометрии) → DETECT (определение позы паллеты по лидару) → ALIGN_COARSE (допуск ±30 мм/±3°) → ALIGN_FINE (целевой допуск ±5 мм/±1°) → READY (взаимное подтверждение готовности) → ENTER (синхронный въезд 0,05–0,10 м/с с контролем отклонения и тока) → LIFT (синхронный подъём с контролем рассинхронизации) → COUPLED (смена футпринта, ограничение скорости, сигнализация) → ERROR (остановка, опускание при частичном подъёме, уведомление). Число автоповторов выравнивания ≤3, после — отказ с уведомлением. Общее время APPROACH→COUPLED ≤90 с. Master переходит к следующему состоянию только после подтверждения slave.

### 5.7. Менеджер миссий

Последовательность: ожидание задачи → проезд → выравнивание/заезд → подъём → транспортировка в связке → опускание → выезд → возврат в ожидание. Таймаут и поведение при отказе на каждом шаге (без потери груза/неуправляемого движения). Отмена задачи оператором на любом шаге. Журналирование состояния миссии, идентификатора паллеты, точек маршрута, результата. После аварии — возобновление только по подтверждению оператора, автоперезапуск не допускается.

### 5.8. Обработка аварийных ситуаций

Таблица событие→реакция→уведомление: E-Stop (обесточивание, фиксация груза, alert+журнал); потеря связи модулей >500 мс (остановка, alert); потеря локализации (остановка, 3 попытки, авария, alert); препятствие в зоне остановки (торможение, ожидание, alert); рассогласование модулей выше порога (остановка, попытка выравнивания, авария с указанием величины); отсутствие ответа контроллера приводов (аварийная остановка модуля и пары, код ошибки); превышение тока/температуры привода (снижение скорости → остановка); перегрузка/заклинивание подъёма (остановка, удержание положения, код ошибки); потеря связи с сервером (завершение задачи до безопасного состояния, режим ожидания); разряд АКБ ниже порога (по п. 4.4); отказ лидара >1 с (аварийная остановка). Все события — в журнал с временной меткой, ID модуля, кодом, снимком телеметрии за 10 с до события. Выход из аварии — только по подтверждению оператора.

### 5.9. Веб-интерфейс оператора

Карта помещения в реальном времени (позиции модулей, траектория, препятствия). Редактор карты (точки/зоны). Постановка задачи (выбор точек на карте, прогресс по шагам). Управление парой (объединение/разъединение, назначение ролей). Кнопка аварийного останова на всех экранах. Панель статуса каждого модуля (режим, скорость, приводы, заряд, подъём, связь, ошибки). Панель уведомлений с историей/фильтрацией/экспортом. Управление картами. Ручной режим (виртуальный джойстик) для наладки. Chrome/Firefox, разрешение ≥1366×768, желательна работоспособность на планшете. Простая парольная защита входа (без ролей/многопользовательского режима на этом этапе).

### 5.10. Диагностика и мониторинг

diagnostic_msgs/DiagnosticArray от всех ключевых узлов. Контроль CPU/памяти вычислителя, состояния узлов ROS 2, задержек master↔slave, частоты критичных топиков. Запись ros2 bag по команде оператора (ротация). Сводная диагностика в веб-интерфейсе. Синхронизация времени модулей (NTP/PTP, расхождение ≤10 мс).

### 5.11. Внешний программный интерфейс

REST/WebSocket: постановка задачи, запрос статуса, отмена, состояние модулей, список карт/точек. Структура сообщений — по образцу VDA 5050 (order, state, action) для минимизации доработок при полной интеграции. Документация — OpenAPI. Полная реализация VDA 5050 (MQTT, полный набор действий) — вне объёма этапа.

### 5.12. Симуляционная модель

URDF/xacro модуля (фактические габариты, суставы, раздельная визуальная/коллизионная геометрия, корректные инерционные параметры). Модель сенсоров (2 лидара, IMU, камеры). Модель пары с параметрическим расстоянием. Модель EUR-паллеты (масса 25–1000 кг параметрически, контактное взаимодействие при подъёме). Модель виртуального склада SDF (≥20×30 м, стеллажи/колонны/стены/ворота/зоны, проходы 1,2/1,5/2,0 м, ≥5 паллет с QR, опционально динамические препятствия). Плагин велосипедной кинематики, ros_gz_bridge, use_sim_time. Параметризованные launch-файлы (одиночный модуль / пара / пара+склад).

### 5.13. Камеры — условная задача

Обязательно: считывание QR передней камерой. Условно (по итогам испытаний лидарного SLAM): визуальная одометрия, детектирование препятствий по камере. Решение — по итогам этапа 2.

### 5.14. Требования к организации разработки

Контроль версий, README на каждый ROS 2 пакет, модульные тесты для алгоритмических компонентов (кинематика, одометрия, детектор паллеты, синхронизация) с автосборкой/автопрогоном. Все пороги/допуски — в YAML без пересборки. Без сторонних платных компонентов; лицензии допускают коммерческое использование, фиксируются в перечне. Исключительные права на создаваемое ПО — у ООО «Тандем Робототехника».
