# Карта репозитория DS-maria-lpf

> **С 27.09.2026 у карты новая роль** (решение Марии, вариант «Б», см. `iwe-development/log.md`, Запись 6 → сверка 27.09.2026).
>
> - **Полнота списка файлов — не здесь.** Полный актуальный список файлов даёт инструмент `personal_list_path` (source: DS-maria-lpf, depth 3) одним вызовом, вместе с заголовком и размером каждого файла. Руками построчный каталог больше не ведётся: он отставал от факта каждую неделю (20.09.2026 — ~15 пропущенных файлов, 27.09.2026 — ~30 и целая папка `astart_2026_osen/`), а файл карты разросся до 50 КБ.
> - **Здесь — только то, чего инструмент не знает:** зачем папка, какой файл главный, какие файлы неочевидны по названию, связи между файлами, какие файлы опасно большие.
> - **Когда править эту карту:** появилась новая папка верхнего уровня (тогда же — строка в README), или файл, назначение которого не читается из имени и заголовка. Обычный файл с понятным заголовком («Экономика ВО 2026», «Транскрипт: Щербаков (3)») сюда не заносится.
> - **Недельная сверка** (на недельной сводке, Хаб): один вызов `personal_list_path` → есть ли новые папки верхнего уровня, которых нет в README и здесь? Больше ничего сверять не нужно.
> - Прежняя полная версия карты (построчный каталог, история ревизий 20.09.2026, инцидент 15.09.2026) — в истории git, коммит `689495844086d0efaf170afcd7e8fe80ca962a24`.
>
> Карта — только структура. Операционные правила — `automation/agent-workflow-rules.md`.

## Pack (`pack/`) — предметное знание доменов

- Pack = что верно про домен всегда; `<slug>/context.md` = что происходит в проекте сейчас.
- `_template.md` — шаблон нового доменного файла; доменные файлы заводятся по первой «Pack-достойной» находке, не заранее.
- `operacionnyj-menedzhment.md` — кросс-проектный метод, **читают все проектные ветки всегда**. Остальные — по домену, назначение видно из заголовка.
