## Недельная сверка: новые папки и сигнал «пора худеть» (с 27.09.2026)

На недельной сводке Хаб делает **один** вызов `personal_list_path` (source: DS-maria-lpf, depth 3) и по нему проверяет две вещи:

1. **Новые папки верхнего уровня**, которых нет в README и в этой карте → предложить Марии строку в README и сюда.
2. **Сигнал «пора худеть»** — только для **живых файлов**, которые правятся часто (context-файлы проектов, портянка, README, дневник, трекер Коуча, служебные: `drr-candidates`, `agent-workflow-rules`, `iwe-development/log`, `nedelnye-svodki`, `otnosheniya-pravila`). Каждая правка перепечатывает файл целиком (у `personal_write` нет режима «дописать») — чем толще живой файл, тем дороже каждая правка и выше риск испортить текст при перезаписи.
   - **≥ 50 КБ — жёлтый:** одна строка в недельной сводке: «файл X — N КБ, пора худеть». Решение — за Марией, не худеть молча.
   - **≥ 70 КБ — красный:** то же, но с пометкой «риск усечения при чтении» (правило 4 в `agent-workflow-rules.md`) и предложением, как именно худеть (вынести дубли в отдельные файлы / архив закрытого / разбить по периоду).
   - **Статичные материалы** (транскрипты, отчёты, выгрузки, архивы) — не сигналят: их пишут один раз, большой размер для них — только риск при чтении, не цена правки.

Сигнал — это только флажок в сводке. Сама разгрузка — отдельным решением, по Gate.

### Дневник-жилетка — нарезка по неделям (с 27.09.2026)

**Правило:** один файл на неделю Пн–Вс, имя `diary-ГГГГ-ММ-ДД-ДД.md` (первый и последний день части). Файл **не пересекает границу месяца**: неделя, которая переходит в следующий месяц, режется на две части (пример: 28–30.09 и 01–04.10). Зачем понедельно: при ~1,5 записи в день полумесячный файл дорастал до 50–90 КБ, а каждая правка перепечатывает его целиком.

**Нужен файл на дату, которой нет в списке ниже** (началась новая неделя) — Дневник сам создаёт файл недели по правилу имени, с шапкой «предыдущая часть — …», и дописывает строку в этот список (правка карты — техническая, без Gate). Прошлые недели после воскресенья не трогаются, кроме дописок задним числом за их даты.

Текущий список:
- `diary-2026-08.md` — август целиком (до введения нарезки).
- `diary-2026-09-01-15.md` — 01–15.09 (полумесячная часть, до введения понедельной нарезки).
- `diary-2026-09-16-20.md` — 16–20.09.
- `diary-2026-09-21-27.md` — неделя 21–27.09.
- `diary-2026-09-28-30.md` — 28–30.09 (сентябрьская часть недели 28.09–04.10).
