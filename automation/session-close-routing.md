# Routing-чек-лист при закрытии сессии

Применяется любой веткой (проектный чат, трек обучения, Хаб) при закрытии сессии — один шаг внутри обычного закрытия, не отдельный протокол с заголовками. Не применяется в ветке «Дневник» — она сама приёмник и интерпретатор, а не маршрутизатор чужого материала. Не применяется в режимах Стратега/Подружки (см. соответствующие промпты).

## Тест (3 вопроса)

Перед закрытием сессии — пройти по тому, что всплыло за сессию:

1. **Есть конкретная задача с дедлайном?** → предложить формулировку → Gate → `docs/portyanka-obshiy-stek.md`.
2. **Есть инсайт, применимый к ДРУГОМУ проекту/треку, не к текущему?** → предложить → Gate → `<slug>/context.md` того проекта.
3. **Есть сырой сигнал о состоянии** (усталость, раздражение, драйв, откладывание — без интерпретации)? → без Gate (это факт, не вывод — см. правило 9 `automation/agent-workflow-rules.md`), одна строка в `telemetry/signals-inbox-<текущий месяц>.md` (формат — см. сам файл).

Ничего из трёх — не задерживать закрытие, не придумывать пункты искусственно.

## Почему пункт 3 без Gate

Правило 9 (`agent-workflow-rules.md`) требует Gate для анализа/выводов агента, не для фактов. Сигнал в инбокс — сырой факт («в 15:40, в чате Тандема, обмолвилась про усталость»), не интерпретация. Интерпретация происходит позже, отдельно, Дневником на вечернем чекине — там уже с Gate (см. раздел EVENING в `prompts/dnevnik-prompt.md`).
