# Routing-чек-лист при закрытии сессии

Применяется любой веткой (проектный чат, трек обучения, Хаб) при закрытии сессии. Не применяется в ветке «Дневник» — она сама приёмник и интерпретатор, а не маршрутизатор чужого материала. Не применяется в режимах Стратега/Подружки (см. соответствующие промпты).

## Явные триггеры закрытия (добавлено 13.09.2026)

Раньше чек-лист полагался на то, что агент сам заметит момент закрытия сессии — фоновая инструкция «при закрытии» без явного крючка. На практике (см. `docs/drr-candidates.md`, PEOPLE INTAKE, и разбор 13.09.2026 про Экстрактор) такие фоновые инструкции ненадёжны. Теперь чек-лист запускается явно одной из фраз Марии: «стоп на сегодня», «на сегодня всё», «закрываем сессию», «запиши файл в репо» — или любой прямой командой зафиксировать что-то в конце разговора.

## Ритуал закрытия — пять блоков, с черновиками (обновлено 13.09.2026)

При срабатывании триггера — не спрашивать «есть ли что-то», а **самому перечитать сессию целиком** (не последнее сообщение) и по каждому из пяти назначений сформулировать конкретный черновик, если материал есть. Раньше это был тест-опросник из 3 пунктов (плюс отдельно для треков обучения) — теперь единый активный ритуал для любой ветки, без разделения.

**Каждый черновик — отдельным блоком, не единым текстом:**

**Блок 1 — Задача с дедлайном.** Черновик формулировки → Gate → `docs/portyanka-obshiy-stek.md`.

**Блок 2 — Инсайт для другого проекта/трека, не текущего.** Черновик → Gate → `<slug>/context.md` того проекта.

**Блок 3 — Доменное знание (роль «Экстрактор», см. `automation/role-trials.md`).** Устойчивый факт о предметной области, который переживёт текущую задачу/проект — не привязан к домену этого чата специфически, а верен про сам домен. Черновик записи → Gate → `pack/<домен>.md` (создать по `pack/_template.md`, если файла для домена ещё нет).

**Блок 4 — Метод/подход к организации работы (тоже роль «Экстрактор»), обобщаемый на ЛЮБОЙ проект, не привязан к конкретному домену.** Как Мария режет задачи, проверяет готовность решения, строит переговоры, принимает решения в моменте — то, что видно в этой сессии как метод, не как содержание конкретной задачи. Черновик → Gate → `pack/operacionnyj-menedzhment.md`.

**Блок 5 — Сырой сигнал о состоянии** (усталость, раздражение, драйв, откладывание — без интерпретации). Без Gate (это факт, не вывод — см. правило 9 `automation/agent-workflow-rules.md`), одна строка → `telemetry/signals-inbox-<текущий месяц>.md` (формат — см. сам файл).

**Gate — по каждому блоку отдельно**, не одним «да» на все сразу. Если по блоку честно нечего предложить — явно написать «Блок N: нечего», не придумывать искусственно.

## Отличие Блока 3 от Блока 4

Блок 3 — про домен («как устроен рынок H₂O₂», «специфика фарм-контрактов») — знание о мире. Блок 4 — про метод Марии («режу задачу через X», «проверяю готовность решения через Y») — знание о том, как она сама работает, но не про её психологию/реакции (это Блок 5, через `signals-inbox` → Дневник разбирает). Пример разграничения: «режу задачу на короткие шаги через технику Х» — Блок 4 (метод); «испытываю тревогу, когда режу задачу» — Блок 5 (реакция).

## Дополнительно для треков обучения — активный перенос в практику (05.09.2026, статус: слито с общим ритуалом 13.09.2026)

Отдельный блок «активный перенос» для треков обучения, существовавший до 13.09.2026, теперь не нужен отдельно — та же логика (не ждать, пока всплывёт само, активно оглядываться на материал целиком) стала нормой для всех веток выше. Специфика треков обучения, которая остаётся: дополнительное назначение — если материал сессии меняет общее направление/видение → черновик → Gate → `docs/videnie.md`.

## Факт прохождения сессии трека обучения (добавлено 14.09.2026)

Отдельно от пяти блоков выше и без Gate (факт, не вывод) — любой трек обучения (FPF, Управление наукой, Распожаризация, IWE/Экзокортекс) при срабатывании триггера закрытия добавляет одну строку в `telemetry/obuchenie-sessii-<текущий месяц>.md` (формат — см. сам файл). Это фиксирует сам факт, что сессия трека состоялась, — независимо от того, дошёл ли материал сессии до `raspozharizaciya/` или другого рабочего файла трека (сессия могла состояться, а запись быть отложена: Gate не пройден, другая ветка занята пересекающимися файлами и т.п., как 14.09.2026). Нужно, чтобы Коуч (`prompts/coach-prompt.md`) мог закрывать привычку «Слот обучения» по факту из файла, а не только по устному отчёту Марии на вечернем чекине.

## Почему Блок 5 без Gate

Правило 9 (`agent-workflow-rules.md`) требует Gate для анализа/выводов агента, не для фактов. Сигнал в инбокс — сырой факт («в 15:40, в чате Тандема, обмолвилась про усталость»), не интерпретация. Интерпретация происходит позже, отдельно, Дневником на вечернем чекине — там уже с Gate (см. раздел EVENING в `prompts/dnevnik-prompt.md`).

## История

- 05.09.2026: создан. Покрывает два случая, обнаруженных в одной сессии: (а) рабочие задачи и инсайты из треков обучения, раньше зависавшие там без переноса в проектные чаты/портянку; (б) сигналы о состоянии из проектных чатов и Хаба, раньше не доходившие до Дневника вообще, пока Мария не пересказывала их сама.
- 05.09.2026 (вечер): добавлен раздел «Дополнительно для треков обучения» — по запросу Марии на активный (не только реактивный) перенос учебного материала в практику; закрывает тот же класс проблемы, что и кандидат «PEOPLE INTAKE не срабатывает как активный триггер» в `docs/drr-candidates.md`.
- 13.09.2026: по итогам разбора мета-ветки IWE — обнаружено, что `pack/` за месяц работы пополнился только из курса обучения и одного разбора Тандема, ни разу из обычных проектных чатов (ПИШ, Химозин, общий ЦПИ+УСС), несмотря на то что роутинг Экстрактора формально существовал. Причина — фоновая «замечай сама» инструкция без явного триггера, тот же класс проблемы, что и PEOPLE INTAKE. Решение: явные триггерные фразы закрытия сессии + чек-лист расширен с 3 до 5 блоков (добавлены доменное знание и метод работы, ранее — только для треков обучения) + активное составление черновиков вместо пассивных вопросов «есть ли что-то» + раздельный Gate по блокам.
- 14.09.2026: добавлена фиксация факта прохождения сессии трека обучения в `telemetry/obuchenie-sessii-<месяц>.md`, отдельно от пяти блоков и без Gate — чтобы Коуч мог заполнять привычку «Слот обучения» из файла, а не только из устного отчёта Марии на вечернем чекине. Повод: сессия трека «Распожаризация» состоялась 14.09.2026, но запись материала была отложена (другая ветка вела пересекающуюся работу по архитектуре) — факт прохождения сессии и факт записи материала оказались независимыми друг от друга и требуют раздельного учёта.
