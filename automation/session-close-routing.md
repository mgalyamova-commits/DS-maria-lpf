# Routing-чек-лист при закрытии сессии

Применяется любой веткой (проектный чат, трек обучения, Хаб) при закрытии сессии. Не применяется в ветке «Дневник» — она сама приёмник и интерпретатор, а не маршрутизатор чужого материала. Не применяется в режимах Стратега/Подружки (см. соответствующие промпты).

## Явные триггеры закрытия (добавлено 13.09.2026)

Раньше чек-лист полагался на то, что агент сам заметит момент закрытия сессии — фоновая инструкция «при закрытии» без явного крючка. На практике (см. `docs/drr-candidates.md`, PEOPLE INTAKE, и разбор 13.09.2026 про Экстрактор) такие фоновые инструкции ненадёжны. Теперь чек-лист запускается явно одной из фраз Марии: «стоп на сегодня», «на сегодня всё», «закрываем сессию», «запиши файл в репо» — или любой прямой командой зафиксировать что-то в конце разговора.

## Ритуал закрытия — восемь блоков, с черновиками (обновлено 02.10.2026 — развилка в Блоке 4, добавлен Блок 8)

При срабатывании триггера — не спрашивать «есть ли что-то», а **самому перечитать сессию целиком** (не последнее сообщение) и по каждому из восьми назначений сформулировать конкретный черновик, если материал есть. Раньше это был тест-опросник из 3 пунктов (плюс отдельно для треков обучения), затем пять блоков (13.09.2026), затем шесть (20.09.2026), семь (27.09.2026) — теперь единый активный ритуал для любой ветки, без разделения.

**Каждый черновик — отдельным блоком, не единым текстом:**

**Блок 1 — Задача с дедлайном.** Черновик формулировки → Gate → `docs/portyanka-obshiy-stek.md`.

**Блок 2 — Инсайт для другого проекта/трека, не текущего.** Черновик → Gate → `<slug>/context.md` того проекта.

**Блок 3 — Доменное знание (роль «Экстрактор», см. `automation/role-trials.md`).** Устойчивый факт о предметной области, который переживёт текущую задачу/проект — не привязан к домену этого чата специфически, а верен про сам домен. Черновик записи → Gate → `pack/<домен>.md` (создать по `pack/_template.md`, если файла для домена ещё нет). Находка с одним случаем — в раздел «Гипотезы (n=1)» файла, с условием «когда применять» и счётчиком; в «Проверено» — только подтверждённое больше одного раза или взятое из надёжного источника.

**Блок 4 — Метод/подход к организации работы (тоже роль «Экстрактор»), обобщаемый на ЛЮБОЙ проект.** Сначала развилка — про что находка (обновлено 02.10.2026; до этого всё, что «не про домен», падало в `pack/operacionnyj-menedzhment.md`, и файл за месяц распух до 66 КБ с шестью разными сущностями внутри):

1. **Про постановку, исполнение, приёмку работы** (как ставить задачу, что считать результатом, как принимать чужую работу, чему верить при анализе операционки) → черновик → Gate → `pack/operacionnyj-menedzhment.md`. Один случай — в «Гипотезы (n=1)».
2. **Про отдельный кросс-проектный метод со своим файлом** — экономика продукта → `pack/ekonomika-produkta.md`; выступления, мероприятия, рассылки, подача модели → `pack/vystupleniya-i-meropriyatiya.md`. Полный список — индекс в шапке `pack/operacionnyj-menedzhment.md`.
3. **Про саму Марию** (как ей удобнее работать, что её цепляет, личные фильтры и решения, саморегуляция) → не Pack: кандидат в `docs/drr-candidates.md`, обычный DRR-поток.
4. **Про общение с людьми** (как вести переговоры, что отвечать, как держать границу) → не Pack: кандидат в `docs/otnosheniya-pravila.md` (по человеку из индекса или в общие правила).
5. **Про технику работы агента или веток** (как писать в репо, как разводить ветки, приёмы сборки файлов) → не Pack: `automation/agent-workflow-rules.md` (правило или кандидат; кейс — в `automation/workflow-incidents.md`). Исключение — приём ремесла, нужный ровно при одном типе РП: его место в том Pack-файле, который читается по этому РП (пример — раздел «Техника сборки материалов» в `pack/vystupleniya-i-meropriyatiya.md`).

Тест на развилку 1 против 3: уберите из формулировки слово «Мария» — если правило осталось осмысленным для любого руководителя, это Pack; если без неё оно распадается («Мария предпочитает…», «мне так легче…») — это DRR.

**Блок 5 — Сырой сигнал о состоянии** (усталость, раздражение, драйв, откладывание — без интерпретации). Без Gate (это факт, не вывод — см. правило 9 `automation/agent-workflow-rules.md`), одна строка → `telemetry/signals-inbox-<текущий месяц>.md` (формат — см. сам файл).

**Блок 6 — Новый человек в разговоре** (добавлено 20.09.2026, DRR). Раньше PEOPLE INTAKE был только у Дневника — люди всплывают во всех рабочих ветках (Тандем, Химозин, ПИШ и т.д.), где такого механизма не было вовсе. Если по ходу сессии упоминался человек, которого нет в `docs/o-marii-fakty-lyudi.md` (по имени или роли) — факт о нём (кто это, роль, откуда, без оценки поведения) → черновик → Gate → `docs/o-marii-fakty-lyudi.md`, напрямую. Похоже на правило коммуникации (не факт «кто это», а «как с ним общаться») → кандидат в `docs/otnosheniya-pravila.md`, через обычный DRR. Этот блок — подстраховка на закрытии, а не единственный момент фиксации: см. также раздел «ЛЮДИ» в `prompts/project-branch-prompt.md` — там та же фиксация, но по ходу разговора, не только на закрытии.

**Блок 7 — Структурное изменение репозитория** (добавлено 27.09.2026). Речь о правках общих/сквозных файлов, не привязанных к одному проекту: промпты ролей и веток (`prompts/*.md`), регламент (`docs/reglament/*`), правила ведения репо (`automation/*.md`); рождение нового домена (новый проект, новая роль, README/repo-map — но только когда домен именно рождается, не рутинная правка внутри существующего); итог DRR-цикла (версия регламента поднялась, что изменилось). Если за сессию было хотя бы одно такое изменение — короткий отчёт (что сделано, что не закончено) → `docs/zhurnal-izmeneniy.md`, append новой секцией `## [ДД.ММ.ГГГГ] Заголовок` (не переписывать прежние записи). Без отдельного Gate по формулировке — сама правка файла уже прошла свой Gate в момент, когда её вносили, здесь только факт «что и когда» (тот же случай, что Блок 5). Не относится к этому блоку: правки `<slug>/context.md` конкретного проекта, статусы/задачи (это портянка, Блок 1), сырые материалы без структурного эффекта, DRR-кандидаты сами по себе (`drr-candidates.md`), если разбор не привёл к правке файла — эти случаи журнал не фиксирует. Повод завести блок: правка `prompts/project-branch-prompt.md` (ритуал слота) 27.09.2026 не попала в журнал сразу, обнаружилось только по прямому вопросу Марии — тот же класс отказа, что и у остальных блоков (фоновая память «запишу как будет крупное» не сработала).

**Блок 8 — Гипотезы Pack: счётчик** (добавлено 02.10.2026). По каждому Pack-файлу, который ветка читала в этой сессии (на старте или по триггеру слота), — пройти раздел «Гипотезы (n=1)» и ответить: была ли в сессии ситуация из строки «когда применять»? Если да — применили гипотезу или нет, сработало или нет. Применили → черновик строки в счётчик пункта («n=2: <проект>, <дата> ✔/✘») → Gate → запись в тот же Pack-файл. Ситуация была, но гипотезу не применили — сказать Марии одной строкой, без записи. Второе-третье ✔ — предложить перенос пункта в «Проверено»; два ✘ — предложить удалить или переписать. Не было ни одной ситуации — «Блок 8: нечего». Зачем: гипотеза, которую только читают, не проверяется — к 02.10.2026 в Pack накопилось 17 пунктов с «n=1», и ни один не получил второго применения, потому что двигать счётчик никто не был обязан.

**Gate — по каждому блоку отдельно**, не одним «да» на все сразу. Если по блоку честно нечего предложить — явно написать «Блок N: нечего», не придумывать искусственно.

## Отличие Блока 3 от Блока 4

Блок 3 — про домен («как устроен рынок H₂O₂», «специфика фарм-контрактов») — знание о мире. Блок 4 — про метод работы, верный в любом проекте («проверяю готовность решения через Y», «принимаю чужой расчёт по сырым строкам») — и развилка внутри него отделяет метод работы от знания о самой Марии. Психология и реакции — не Блок 4 вообще: сырой сигнал идёт в Блок 5 (`signals-inbox` → Дневник разбирает), устойчивый личный паттерн — кандидатом в DRR (развилка 3 Блока 4). Пример разграничения: «отчёт по этапу обязан содержать сверку план/факт» — Блок 4, развилка 1 (метод); «Мария предпочитает забрать таблицу и разметить сама» — Блок 4, развилка 3 (DRR); «испытываю тревогу, когда режу задачу» — Блок 5 (реакция).

## Дополнительно для треков обучения — активный перенос в практику (05.09.2026, статус: слито с общим ритуалом 13.09.2026)

Отдельный блок «активный перенос» для треков обучения, существовавший до 13.09.2026, теперь не нужен отдельно — та же логика (не ждать, пока всплывёт само, активно оглядываться на материал целиком) стала нормой для всех веток выше. Специфика треков обучения, которая остаётся: дополнительное назначение — если материал сессии меняет общее направление/видение → черновик → Gate → `docs/videnie.md`.

## Почему Блок 5 без Gate

Правило 9 (`agent-workflow-rules.md`) требует Gate для анализа/выводов агента, не для фактов. Сигнал в инбокс — сырой факт («в 15:40, в чате Тандема, обмолвилась про усталость»), не интерпретация. Интерпретация происходит позже, отдельно, Дневником на вечернем чекине — там уже с Gate (см. раздел EVENING в `prompts/dnevnik-prompt.md`).
