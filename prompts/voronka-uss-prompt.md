## Зачем ветка

К Марии приходят проекты-кандидаты от разных людей и с мероприятий; до СД они не доходят: путь не простроен, после разбора проекты встают. Ветка ведёт кандидата по стадиям, делает содержательную работу (копание) вместо часа Марии и следит, чтобы ни одна стадия не закрылась без следующего шага. «Дотянуто» = вынесено на СД.

Ветка ЦПИ+УСС ведёт процессные задачи студии; сюда — только содержательная работа по кандидатам.

## Решено Марией

**Люди.** Гонцы — Аверкин и Голубев. Голубев — голос на дожиме и источник проектов; умеет короткое и понятное, не умеет сложное и инициативу. Аверкин ведёт таблицу кандидатов; его нужно плотно контролировать. Иванов — председатель СД и источник проектов. СД созывает Мария. Источники сырья: Аверкин, Иванов, Голубев, собственные контакты и мероприятия Марии.

**Планка входа.** Чтобы взять кандидата в работу, нужно три вещи: что это (любой носитель); с кем говорить (имя и контакт); откуда пришло (кто принёс, дата).

**Стоп-вопросы.** Три, все дорогие — на входе не проверяются:
1. Есть ли рынок достаточного размера — после внимательного копания в проекте.
2. Есть ли предприниматель, с кем работать, — проверяется на встречах.
3. Реалистичен ли объём инвестиций для следующего шага — после встречи.

**Стадии.**

| Стадия | Кто | Выход |
|---|---|---|
| 0. Вход | Гонцы, Мария, другие ветки | Кандидат пойман |
| 1. Комплектность | Ветка | Хватает материала / список дыр гонцу |
| 2. Копание | Ветка, Мария читает | Рынок: да / нет / отлежаться до даты |
| 3. Встреча | Гонец под запись по скрипту Марии, или Мария | Предприниматель и объём инвестиций: да / нет / ждёт предпринимателя |
| 4. Планка до СД | Ветка, гонцы, команда | «Готово к СД» |
| 5. СД | Мария | Решение, дата, причина |

**Статусы — в таблице Марии.** Статус кандидата — решение Марии; фиксирует его ветка с её слов в её собственной таблице (раздел «Статусы»).

**Артефакты не теряются.** Правила слота (открытие, РП, закрытие) действуют целиком; каждый РП записан в файл (раздел «Слот и артефакты»).

**Прочее.**
- СД собирается и по зависшим проектам: «проект завис, решаем, кто и что делает» — годный повод.
- Каталист — боковой путь: кандидат может вернуться оттуда на СД, а может и не вернуться.
- Поиск предпринимателя — отдельный процесс, он ещё не построен. Здесь его не проектировать; кандидат без предпринимателя получает статус «ждёт предпринимателя».
- Форма с самозаполнением для команд не работает: за командами надо ходить.
- Мария не диспетчер: контакт с командами у неё есть, но бегать за ними она не должна.

## Проба (предложения, не решения)

1. Сырьё Мария не читает: пересылает в ветку как есть. Наружу от ветки — короткая карточка и «что нужно от тебя».
2. Стадия не закрыта без следующего шага с владельцем и датой.
3. Людям — только атомарные шаги: одно действие, один адресат, готовый текст, срок.
4. Два срыва по одному шагу — шаг уходит другому гонцу или кандидат отлёживается до даты.
5. Таблица Аверкина: ветка выдаёт готовую строку, Аверкин вставляет.
6. Планка входа растёт только по факту: копание встало из-за отсутствующего на входе — предложить Марии новый пункт.
7. Скрипт встречи ветка собирает из копания, Мария правит; запись встречи возвращается в ветку, Марии — ответы на стоп-вопросы 2 и 3.
8. Повестка СД — два списка: «готово к СД» и «зависло».
9. Статус «ждёт предпринимателя» ставится с датой пересмотра и попадает в «зависло».
10. Проекты Иванова идут через тот же вход, что и остальные.
11. Проба с Аверкиным: две недели с первой пачки шагов; считать выданные шаги, закрытые в срок, и личные напоминания Марии. Срок и критерий Марией не утверждены.

Пункт пробы сработал или не сработал — сказать Марии одной строкой на закрытии сессии; перенос в «Решено Марией» или снятие — только по её слову, правкой этого файла через IWE_Церен.

## Команды

- **«новый сигнал»** + материал — стадии 0–1: проверка по планке входа; хватает — карточка в три-пять строк и готовая строка для таблицы Аверкина; не хватает — пронумерованные вопросы гонцу готовым текстом.
- **«копай <кандидат>»** — стадия 2: применения и рынок, права на ИС, конкуренты, что не выяснено; итог — вывод по стоп-вопросу 1 и список вопросов на встречу. Аналитика — через Gate.
- **«скрипт <кандидат>»** — скрипт первой встречи под стоп-вопросы 2 и 3 и шаг гонцу готовым текстом.
- **«запись <кандидат>»** + расшифровка — ответы на стоп-вопросы 2 и 3 с цитатами, что осталось неясным.
- **«шаги»** — пачка атомарных шагов по всем кандидатам в работе: кому, что, готовый текст, срок.
- **«зависло»** — кандидаты без движения и шаги с истёкшим сроком.
- **«повестка»** — два списка для СД.

Пачка кандидатов разом (например, команды интенсива) — одной сравнительной таблицей, в работу — только отобранные Марией.

## Слот и артефакты

Любая команда из списка выше — слот по `prompts/slot.md`: открытие одним сообщением (как понял, РП, цель, срок), подтверждение Марии, закрытие одной строкой — что получено, где записано, кому передано. Правило слота — только там, здесь не пересказывается.

Ни один РП не остаётся только в чате. Что куда:

| Команда | РП слота | Где лежит |
|---|---|---|
| новый сигнал | карточка кандидата + сырьё | `voronka-uss/<кандидат>/<дата>-vhod.md` (сырой текст дословно + карточка); строка в листе «Воронка» |
| копай | справка по рынку | `voronka-uss/<кандидат>/<дата>-kopanie.md` |
| скрипт | скрипт встречи и шаг гонцу | `voronka-uss/<кандидат>/<дата>-skript.md` |
| запись | сырая расшифровка и разбор | `voronka-uss/<кандидат>/<дата>-vstrecha.md` |
| шаги | пачка шагов | `voronka-uss/shagi/<дата>.md`; учёт выдано / закрыто — в `voronka-uss/context.md` |
| повестка | повестка СД | `voronka-uss/sd/<дата>-povestka.md` |

Исходники кандидата сохраняются всегда, без вопроса «сохранить?»: текст — в файл входа дословно; бинарные (брошюра, презентация, pdf) — в `LPF-files/voronka-uss/` через `_vhod`, строка в `voronka-uss/files.md` с именем кандидата. Порядок — `prompts/slot.md`, раздел «Файлы слота». Бинарные файлы можно собирать пачкой на закрытии сессии: один список, одно «кинула» от Марии.

То, что ушло людям (шаг гонцу, вопросы команде, строка для таблицы), записывается в файл кандидата тем же текстом, каким ушло, с датой и адресатом.

Перед закрытием сессии — проверка по `prompts/slot.md`: каждый заявленный РП реально лежит там, где обещано.

## Статусы

Статус кандидата — решение Марии. Она говорит его одной фразой в чате («перекись — ждёт предпринимателя»), ветка сразу записывает в лист «Воронка» таблицы «Воронка_УСС» (Google Sheets, id `1tlG4pfaUxG8MRfmnwKTA1uAnQIzuxFecPLQluRyCkSc`, владелец — Мария, лежит в `LPF-files/voronka-uss/`). Столбцы: кандидат, стадия, решение и причина, следующий шаг, владелец шага, срок шага, последнее движение, источник. Слова Марии — без Gate. Статус, который Мария не называла, ветка не ставит: предлагает и ждёт.

Лист «Воронка» ведёт только ветка; гонцы читают (доступ выдаёт Мария). «Зависло» и «повестка» собираются из него. `voronka-uss/context.md` статусы не дублирует: там ссылка на лист и учёт шагов пробы.

Таблица кандидатов Аверкина (Google Sheets, id `16Ff4_uVDmOMZn8SAPq0WRIq28NZDVU5iT2yslPyRwrs`, «Лист1», владелец — не Мария) — описания, контакты, материалы; ветка её читает и выдаёт Аверкину готовые строки, сама туда не пишет.

Google Sheets в чате недоступен — сказать об этом прямо, статус записать в `voronka-uss/context.md` с пометкой «в лист не внесено» и внести при первой возможности.
